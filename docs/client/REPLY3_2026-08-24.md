## 1. 403エラーについて｜設定が1つ足りないだけです

**エラーの内容は「異常」ではありません。** 設定が1つ抜けているだけで、
1分で解決します。

### なぜ出ているか

Googleは、作ったばかりのアプリを「テスト中」の状態にします。
このとき、**「使ってよい人」のリストに自分を登録しておく**必要があります。

いまはそのリストが空なので、
オーナーであるご自身でさえ弾かれている、という状態です。

### 解決手順（1分）

**① 下のページを開いてください**

https://console.cloud.google.com/auth/audience

（`sociallink555@gmail.com` でログインした状態で開いてください）

**② 「テストユーザー」の欄を探します**

ページの下のほうに **「テストユーザー」**（Test users）という項目があります。

**③ 「+ ADD USERS」ボタンを押します**

**④ ご自身のメールアドレスを入力して保存**

```
sociallink555@gmail.com
```

**⑤ 保存できたら、下のURLをもう一度開いてください**

```
https://accounts.google.com/o/oauth2/auth?response_type=code&client_id=584713638505-a62ctb0mi8gkagr5rp19d83fmh9h7rj7.apps.googleusercontent.com&redirect_uri=http%3A%2F%2Flocalhost%3A1&scope=https%3A%2F%2Fwww.googleapis.com%2Fauth%2Fspreadsheets.readonly&state=JLJOMyov8UqNA5U0pZIm2I5mnOGUuJ&code_challenge=VkgTxptMbk7IKuYvVYQm0AgOd7G0T6MjZUAy8NmYjOM&code_challenge_method=S256&access_type=offline&prompt=consent
```

これで承認画面が正常に表示されます。

> 「このアプリは Google で確認されていません」と出た場合は、
> **「詳細」→「（プロジェクト名）に移動」** で進んでください。
> ご自身で作成したアプリですので問題ありません。

### 承認後の流れ（前回と同じです）

1. 承認すると、ブラウザが **エラー画面**（localhost に接続できません）になります
   → **これは正常です**
2. そのエラー画面の **アドレスバーのURL全体** をコピーしてお送りください
   （`http://localhost:1/?code=4/0AVG7f...` のような長いURL）

## 2. ネームサーバーとロリポップについて｜ご回答

### 結論：**別のものです。ロリポップは今回いっさい関係ありません。**

ご契約中のロリポップに影響は出ませんので、ご安心ください。

### 違いのご説明

例えるなら、こうなります。

| | 役割 | 例えると |
|---|---|---|
| **ネームサーバー（DNS）** | その住所がどの建物かを案内する | **住所の案内板** |
| **サーバー（ロリポップ等）** | 実際にファイルやサイトが置かれる場所 | **建物そのもの** |

今回変更するのは **案内板のほう** だけです。
ロリポップという「建物」には、いっさい手を触れません。

### 実際に確認しました

`social-ai01.com` が現在どこを向いているか調べたところ、

> **「このドメインはお名前.comで取得されています」**

という、お名前.comの**初期パーキングページ**が表示される状態でした。

つまり、

- このドメインは **ロリポップに向いていません**
- このドメインで動いている**サイトもメールもありません**
- 変更しても **止まるものが何もありません**

ロリポップは別のドメインでお使いかと思いますが、
そちらはこの作業とは完全に無関係ですので、影響を受けません。

### なぜ Cloudflare をおすすめするのか

ロリポップは「Webサイトを置くためのサーバー」で、
SOCIALのようなプログラムを常時動かすことができません。
そのため、SOCIAL本体は別のサーバーで動かします。

そのうえで Cloudflare を使う理由は、主に3つです。

**① セキュリティ**
サーバーを直接インターネットに晒さずに済みます。
外部からの不正アクセスの入り口を作りません。

**② SSL証明書（鍵マーク）が自動**
`https://` の設定・更新を自動でやってくれます。手間も費用もかかりません。

**③ 本番移行のときに設定変更が不要**
将来サーバーを本番用に移すとき、**ドメイン設定を触らずに済みます**。
この先の作業を減らせる、というのが実は一番大きな理由です。

**費用は無料プランで足ります。** 追加のご負担はありません。

### 将来ロリポップでサイトを作りたくなった場合

`social-ai01.com` でホームページも作りたい、となった場合でも問題ありません。
Cloudflareの管理画面から、ロリポップを指す設定を追加するだけです。
**選択肢が狭まることはありません。**
